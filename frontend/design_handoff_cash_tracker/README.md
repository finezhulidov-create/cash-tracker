# Handoff: Cash Tracker — веб-фронтенд

## Overview
Адаптивный веб-клиент для backend-проекта **cash-tracker** (Spring Boot, JWT). Покрывает весь текущий API: вход/регистрация, дашборд месяца, траты со сплитами (одна трата → несколько категорий), бюджеты (лимит / потрачено / остаток), аналитика по категориям и по месяцам, категории, профиль с ручным балансом. Темы: светлая / тёмная / системная. Визуальная идея — нейтральный Chakra UI + «переливающиеся» (iridescent) градиенты на ключевых поверхностях.

## About the Design Files
Файлы в этой папке — **дизайн-референсы, сделанные в HTML**: прототип показывает внешний вид и поведение, это **не продакшен-код для копирования**. Задача — **воссоздать дизайн в новом фронтенд-приложении** на выбранном стеке, с реальными запросами к API.

Рекомендуемый стек (дизайн собран на токенах Chakra UI v3, поэтому перенос 1:1):
- **React + TypeScript + Vite** (порт 5173 уже разрешён в `app.cors.allowed-origins`)
- **@chakra-ui/react v3** с дефолтной темой (имена токенов в прототипе = токены Chakra: `pink.300`, `bg.panel`, `fg.muted`…)
- **TanStack Query** для запросов, **React Router** для экранов, **next-themes** для темы (стандартный color-mode Chakra v3)
- Иконки — **lucide-react** (в прототипе — те же Lucide SVG)

Как открыть прототип: запустить любой статический сервер в этой папке (`npx serve .`) и открыть `Cash Tracker.dc.html`. Панель Tweaks (dashboardVariant, intensity, shimmer, device, authScreen) — только для просмотра, в продакшен не переносится.

## Fidelity
**High-fidelity.** Цвета, типографика, отступы, состояния и взаимодействия финальные. Воспроизводить точно, используя компоненты Chakra UI v3. Демо-данные (суммы, траты) — фиктивные, заменяются ответами API.

## Адаптивность
Брейкпоинты считаются по ширине окна:
| Ширина | Режим | Навигация |
|---|---|---|
| `< 720px` | Телефон | Верхняя шапка 56px (лого, заголовок, кнопка темы, аватар) + **нижний таб-бар** 68px: Обзор, Операции, [кнопка «+»], Бюджеты, Аналитика. Профиль — по аватару, Категории — из профиля |
| `720–1099px` | Планшет | Боковая колонка иконок 76px (без подписей, `title` = подпись) |
| `≥ 1100px` | Десктоп | Боковое меню 248px с подписями и карточкой пользователя внизу |

- Контент: `max-width: 1240px; margin: 0 auto`. Паддинги страницы: телефон `16px 16px 104px` (снизу место под таб-бар), планшет `24px 24px 48px`, десктоп `28px 40px 56px`.
- Все ряды карточек — `flex-wrap` с `flex-basis` (например `2 1 520px` / `1 1 300px`), сетки — `repeat(auto-fill, minmax(min(100%, 280px), 1fr))`. Никаких фиксированных ширин у текстовых блоков.
- Hit-targets на телефоне ≥ 44px. Учитывать `env(safe-area-inset-bottom)` в таб-баре и в шторке.

## Screens / Views

### 1. Вход / Регистрация
- **API**: `POST /auth/login` `{email, password}` → `TokenResponse {accessToken, tokenType, expiresIn}`; `POST /auth/register` `{email, username, password}` → `TokenResponse`/`RegisterUserResponse`. Хранить токен, слать `Authorization: {tokenType} {accessToken}`. По истечении `expiresIn` / на 401 → на экран входа.
- **Layout**: десктоп/планшет — две колонки: слева iridescent-панель (flex `1.1`, `min-height:100vh`, padding `40px 48px`), справа форма (max-width 400px, центр). Телефон — колонка: панель сверху (min-height 300px, padding `24px 20px 32px`), форма ниже.
- **Панель**: лого; заголовок «Каждый рубль — на своём месте» (Wix Madefor 600, 60px десктоп / 36px телефон, line-height 1.1, `-0.025em`); фраза «на своём месте» — highlight-мотив Chakra: полупрозрачная плашка + `border-right: 2px solid currentColor`, скругление только слева. Подзаголовок 18px. Внизу (не на телефоне) 3 пункта в формате «**Сплиты.** описание» (описание приглушено).
- **Форма**: переключатель темы (справа сверху); заголовок «С возвращением» / «Создать аккаунт» (30px, 600); SegmentGroup на всю ширину «Вход | Регистрация»; поля size `lg` (44px): Имя (только регистрация), Email, Пароль; кнопка на всю ширину «Войти» / «Создать аккаунт».
- **Валидация** (повторяет бэкенд): email валидный; регистрация — имя 2–20 символов, пароль 8–72. Ошибка показывается под полем пароля (`Field invalid` + error text). 409 `EMAIL_ALREADY_EXISTS` → «Этот email уже зарегистрирован». 429 (rate limit /auth/**) → «Слишком много попыток, попробуйте через минуту».

- **Ряд 1**:

Текст: «Потрачено в октябре» (14/500, приглушённо) → сумма `totalSpent` (Wix Madefor 600, 56px / 40px на телефоне, tabular-nums, `-0.025em`) → «из {overall.assigned} общего бюджета». Справа — кнопка-чип «Баланс» (фон белый 45% / в тёмной белый 14%, blur 8px) → переход в Профиль. Внизу прогресс-бар 10px (трек чёрный 12% / белый 18%, заливка `gray.950` / белая), подписи «Осталось X · N% бюджета» и «≈ X в день · ещё N дней» (остаток / оставшиеся дни месяца включая сегодня).
  - *По категориям* (flex `1 1 300px`): донат 140px, толщина кольца 18px, в центре «N категорий» + сумма; легенда: квадрат 10px с градиентом категории, имя, процент.
- **Ряд 2**:
  - *Бюджеты* (flex `1 1 340px`): строки по `categories[]` — иконка категории в плашке 28px, имя, «потрачено / лимит», бар 6px (градиент категории; при перерасходе `red.400→red.600`), статус: «Осталось X» (`fg.muted`), ≥85% — `fg.warning` 600, перерасход «Перерасход X» — `fg.error` 600. Справа сверху «В среднем X в месяц».

### 3. Операции
- **API**: `GET /v1/transactions?page&size=20&sort=dateTime,desc&categoryId&minAmount&maxAmount&from&to` (PagedModel). `from/to` — `LocalDateTime` ISO (`2026-10-01T00:00:00` / `2026-10-31T23:59:59`).
- **Поиск по описанию**: в `TransactionSearchCriteria` такого поля нет. Варианты: добавить параметр `q` на бэкенде (рекомендуется) или фильтровать загруженную страницу на клиенте.
- **Layout**: строка: поле поиска с иконкой (flex `1 1 260px`) + кнопка «Фильтры» (outline; открыто — subtle; бейдж с числом активных фильтров). Панель фильтров (по умолчанию открыта на десктопе): сетка `auto-fill minmax(170px,1fr)` — Категория (NativeSelect, «Все категории»), Сумма от, Сумма до, Дата с, Дата по; кнопка ghost «Сбросить фильтры» (disabled, если фильтров нет). Строка «N операций · Итого X». Список сгруппирован по дню: заголовок группы «Сегодня, 28 октября» / «Вчера, …» / «24 октября, суббота» + сумма дня; группа — стеклянный контейнер, строки 64px как на дашборде; для сплита бейдж «2 части» (скрыт на телефоне). Пагинация — бесконечная прокрутка или «Показать ещё».
- **Пусто**: EmptyState «Ничего не найдено» / «Попробуйте изменить фильтры или сбросить их» + «Сбросить всё».

### 4. Добавление / редактирование траты (выезжающая панель)
- **API**: `POST /v1/transactions` `{description, amount, dateTime, splits:[{categoryId, amount}]}`; `PUT /v1/transactions/{id}` (те же поля, `dateTime` обязателен); `DELETE /v1/transactions/{id}`. 400 при несовпадении суммы частей.
- **Открытие**: кнопка «Добавить трату» (header), «+» в таб-баре, клик по любой операции (режим редактирования).
- **Контейнер**: десктоп/планшет — правая панель `width: min(480px, 100vw)`, на всю высоту, `translateX(105%) → 0`; телефон — нижняя шторка от `top: 6vh`, скругление сверху 16px, «ручка» 40×4px, `translateY(105%) → 0`. Анимация 380ms `cubic-bezier(0.21,1.02,0.73,1)`. Подложка `rgba(0,0,0,0.36)`, fade 250ms, клик по ней или Esc закрывает. `role="dialog" aria-modal`.
- **Поля**: «Сумма» — большой flushed-инпут (Wix Madefor 600, 40px, высота 64px) + «₽» 36px `fg.muted`; «Описание»; «Дата» + «Время» (сетка 1.4fr / 1fr).
- **Блок «Разбивка по категориям»** (фон `bg.subtle`, граница `border.muted`, радиус 6px, padding 16px):
  - Сегментированный бар 8px: доли частей в цвете категорий, нераспределённый остаток — штриховка.
  - Одна часть: только выбор категории — вся сумма уходит в неё.
  - «Разделить на ещё одну категорию» (outline, пунктир, на всю ширину): первая часть получает всю сумму, добавляется строка со следующей неиспользованной категорией. Строка части: цветной квадрат, select категории, сумма (112px, выравнивание вправо), кнопка ×. Удаление до одной части возвращает режим «вся сумма».
  - «Поровну» (ghost) — делит сумму на N частей, копейки уходят в последнюю.
  - Строка статуса с иконкой: «Введите сумму траты» (muted) · «Вся сумма — в категории «Еда»» (success) · «Осталось распределить X» (warning) + кнопка «Добавить остаток» · «Части больше суммы на X» (error) · «Сумма частей совпадает с суммой траты» (success) · «Добавьте описание траты».
- **Футер**: (редактирование) «Удалить» — ghost red, первый клик меняет на solid «Точно удалить?»; справа «Отмена» (outline) и «Сохранить» (iridescent; disabled, пока статус не success и нет описания).
- После сохранения/удаления — toast и инвалидация списков/сводки.

### 5. Бюджеты
- **API**: `GET /v1/analytics/summary?yearMonth=` (статусы общего и по категориям); `POST /v1/budgets` `{amount, period: 'YYYY-MM-01', categoryId|null}`; `PUT /v1/budgets/{id}` `{limitAmount, period}`; `DELETE /v1/budgets/{id}`. 409 — бюджет на эту категорию и месяц уже есть.
- **Layout**: навигатор месяца (‹ «Октябрь 2026» ›, 18px 600, min-width 150px), справа «Новый бюджет» (outline) → инлайн-форма: «На что» (Общий бюджет на месяц / категории без бюджета), «Лимит на месяц, ₽», «Отмена» / «Создать».
- **Общий бюджет** — iridescent-карточка: «Общий бюджет на месяц», кнопка-чип «Изменить» (инлайн-редактирование лимита), 3 колонки Лимит / Потрачено / Осталось (или «Перерасход»), 30px 600; прогресс 10px. Если нет — пунктирная плашка «Общий бюджет не задан» + «Задать лимит».
- **Карточки категорий** — сетка `auto-fill minmax(280px,1fr)`: иконка 36px, имя, кнопки ✎ и 🗑 (xs ghost), «потрачено» (24px 600) «из лимит», бар 8px, Badge subtle (green «Осталось X» / orange ≥85% / red «Перерасход X»), процент.
- Ниже: «Без лимита:» — кнопки-чипы категорий без бюджета, клик открывает форму с выбранной категорией. Пустой месяц — EmptyState «На ноябрь бюджетов нет».

### 6. Аналитика
- **API**: `GET /v1/analytics/by-category?from=YYYY-MM-DD&to=YYYY-MM-DD` → `CategorySpendingDto[] {categoryId, categoryName, spent}`; `GET /v1/analytics/monthly?year=` → `MonthlySpendingDto[] {month, spent}`.
- *Траты по категориям*: SegmentGroup «Месяц | 3 месяца | Год» (задаёт from/to), подпись периода «1 — 31 октября 2026». Донат 240px (200 на телефоне), толщина 26px, в центре «Всего». Список: иконка 32px, «Имя N%», сумма, бар 6px (ширина относительно максимальной категории).
- *Траты по месяцам*: навигатор года, 3 метрики (За год / В среднем за месяц / Самый затратный месяц), столбцы высотой 260px (200 на телефоне), над столбцом короткое значение «15,4к» (скрыто на телефоне), `title` с полной суммой.

### 7. Категории
- **API**: `GET /v1/categories/mine`, `POST /v1/categories` `{categoryName}` (1–50), `PUT /v1/categories/{id}`, `DELETE /v1/categories/{id}` (409 `CATEGORY_IN_USE`), `GET /v1/categories/{id}/splits?size=1` → `totalElements` для счётчика.
- **Layout** (max-width 760px): карточка «Новая категория» (input + «Добавить»; дубль имени → ошибка «Категория «X» уже есть»). Список в стеклянном контейнере: иконка 40px, имя, мета «N частей трат · X в октябре» / «Пока без трат», ✎ (инлайн-переименование с ✓/×), 🗑. При `CATEGORY_IN_USE` под строкой Alert warning: «Нельзя удалить «Еда»» — «К категории привязано N частей трат. Перенесите их в другую категорию — так история останется целой.»
- **Цвет и иконка категории**: в API их нет — назначаются на клиенте детерминированно: палитра по `id % 9` (см. токены), иконка по имени (Еда → `shopping-basket`, Транспорт → `bus`, Квартплата → `house`, Кафе → `coffee`, Подписки → `repeat`, Здоровье → `heart-pulse`), иначе `tag`.

### 8. Профиль
- **API**: `GET /v1/users/me` → `{name, email, balance}`; `PUT /v1/users/me/balance` (значение ≥ 0).
- **Layout**: сетка `auto-fit minmax(340px,1fr)`: (1) аватар xl в iridescent-кольце 3px + имя (20px 600) + email; (2) «Баланс»: сумма 36px 600 с iridescent-градиентом по тексту (`background-clip: text`, pink.500→purple.500→blue.500→cyan.500→teal.500), «Изменить» → инлайн-инпут + «Сохранить», подпись «Задаётся вручную и не меняется от трат»; (3) «Тема оформления» — SegmentGroup «Светлая | Тёмная | Системная» + подсказка «Повторяет настройки устройства — сейчас тёмная»; (4) ссылки «Категории N ›» и «Выйти» (`fg.error`, hover `bg.error`).

## Interactions & Behavior
- **Тема**: light / dark / system, хранится в `localStorage`; system слушает `prefers-color-scheme` в реальном времени. Переключение — класс `.dark` на `<html>` (стандарт Chakra v3 + next-themes). На телефоне кнопка в шапке циклично меняет light → dark → system (иконка отражает текущий режим).
- **Toast** (Chakra Toast): 2.8s; десктоп — справа снизу (24px), телефон — по центру над таб-баром (84px). Тексты: «Трата добавлена · Супермаркет · 3 240 ₽», «Изменения сохранены», «Трата удалена», «Бюджет создан», «Лимит обновлён», «Категория добавлена/удалена», «Баланс обновлён».
- **Hover**: строки списков → `bg.muted` 150ms; кнопки — по рецептам Chakra. Фокус — 2px ring с offset 2px (Chakra по умолчанию).
- **Loading**: Skeleton (Chakra) на месте карточек и строк; кнопки сохранения — `loading`.
- **Ошибки API**: тело `ErrorResponse {status, message, errorCode, errors?}` — `errors` раскладывать по полям форм; прочее — toast error.
- **Motion**: бары/кольца анимируют `width/height` 400ms; iridescent-слои — см. ниже. Учитывать `prefers-reduced-motion: reduce` → отключить анимацию перелива и аур.
- **Форматирование**: `Intl.NumberFormat('ru-RU', {maximumFractionDigits: 2})` + неразрывный пробел + «₽»; суммы — `font-variant-numeric: tabular-nums`. Ввод сумм принимает запятую и точку. Дата/время траты собираются в `LocalDateTime` без TZ (`2026-10-28T14:30:00`). Склонения: «1 трата / 2 траты / 5 трат», «часть / части / частей», «день / дня / дней».
