# Cash Tracker — веб-клиент

Адаптивный клиент для бэкенда Cash Tracker: вход и регистрация, обзор месяца, траты со сплитами (одна трата — несколько категорий), бюджеты, аналитика, категории, профиль. Светлая, тёмная и системная темы.

Дизайн: [`design_handoff_cash_tracker/README.md`](design_handoff_cash_tracker/README.md) (папка с прототипом оставлена как референс, в сборку, линтер и проверку типов она не входит).

## Стек

| Что | Чем |
|---|---|
| Основа | React 19, TypeScript (strict), Vite |
| UI | Chakra UI v3 (токены дизайна), иконки lucide-react, шрифты Inter и Wix Madefor Text через `@fontsource` |
| Данные | TanStack Query v5, собственный `fetch`-клиент |
| Маршруты | React Router 7, экраны подгружаются лениво |
| Тесты | Vitest, Testing Library, MSW |

## Запуск

Нужен Node.js 22.12 или новее. Бэкенд должен быть запущен на `http://localhost:8080` (`docker compose up --build` в корне репозитория), CORS для `http://localhost:5173` в нём уже разрешён.

```bash
npm install
npm run dev          # http://localhost:5173
```

| Команда | Что делает |
|---|---|
| `npm run dev` | dev-сервер с горячей перезагрузкой |
| `npm run build` | проверка типов и production-сборка в `dist/` |
| `npm run preview` | локальная раздача собранного `dist/` |
| `npm run typecheck` | только проверка типов |
| `npm run lint` | ESLint |
| `npm test` | все тесты один раз (`npm run test:watch` — в режиме наблюдения) |

## Настройка

Адрес API задаётся переменной `VITE_API_URL` на этапе сборки. В разработке она лежит в `.env.development` (`http://localhost:8080`).

```bash
# сборка для продакшена с другим адресом API
VITE_API_URL=https://api.example.com npm run build
```

Если переменная не задана, запросы идут на тот же адрес, откуда загружен сайт: так клиент работает за обратным прокси, который отдаёт статику и проксирует `/auth` и `/v1` на бэкенд. Для отдельного домена API добавьте адрес сайта в `app.cors.allowed-origins` бэкенда.

`dist/` — обычная статика. Для SPA сервер должен отвечать `index.html` на неизвестные пути (например, `try_files $uri /index.html` в nginx).

## Как устроено

```
src/
├── api/            fetch-клиент (ошибки в формате ErrorResponse, Authorization, сброс сессии на 401),
│                   типы DTO, функции эндпоинтов, хуки TanStack Query и ключи кэша
├── auth/           сессия (токен + срок жизни в localStorage), защищённые маршруты
├── theme/          система Chakra (шрифты, keyframes, переменные «перелива»), провайдер темы
├── components/     общие части: карточка-«стекло», перелив, донат, прогресс-бар, строка траты…
├── layout/         боковое меню, шапки, таб-бар телефона, три режима раскладки
├── features/       экраны: auth, dashboard, transactions, budgets, analytics, categories, profile
├── lib/            чистые функции: деньги, даты, склонения, расчёт сплитов, цвета категорий
└── test/           инфраструктура тестов (MSW-сервер, рендер с провайдерами, фикстуры)
```

**Раскладка** переключается по ширине окна: до 720 px — телефон (шапка и нижний таб-бар с кнопкой «+»), 720–1099 — планшет (колонка иконок), от 1100 — десктоп (меню с подписями).

**Сессия.** Токен и момент его истечения хранятся в `localStorage` (ключ `ct.session`). Когда токен истекает или бэкенд отвечает 401, сессия сбрасывается, кэш запросов очищается и пользователь попадает на экран входа. Ответы `/auth/*` с 401 сессию не трогают: это просто неверный пароль.

**Деньги.** В запросах и ответах суммы — числа; внутри форм сумма хранится строкой, а разбивка траты считается в копейках (целые числа), чтобы сумма частей сходилась без ошибок плавающей точки. Ввод принимает и запятую, и точку. Дата и время траты отправляются без часового пояса (`2026-10-28T14:30:00`), как этого ждёт бэкенд.

**Цвет и иконка категории** в API не хранятся: цвет выбирается по `id` (девять градиентов палитры), иконка — по названию («Еда» → корзина, «Транспорт» → автобус…), для остальных — тег.

**Операции.** Фильтры и поиск лежат в URL (`?q=кофе&cat=3&min=100&from=2026-10-01`), поэтому вид можно сохранить в закладку. Поиск по описанию — параметр `q` бэкенда. Конец периода «Дата по» уходит как `T23:59:59.999999`, чтобы захватить весь день. Сумма «Итого» считается по загруженным операциям, пока список не загружен целиком, подпись меняется на «Загружено на».

**Бюджеты.** Остатки считает бэкенд (`GET /v1/analytics/summary`). Смена категории у существующего бюджета в API не предусмотрена: нужно удалить его и создать заново.

## Тесты

```bash
npm test
```

Сетевой слой мокается на уровне HTTP (MSW), поэтому тесты гоняют настоящий код: `fetch`-клиент, хуки TanStack Query, формы и маршрутизацию. Покрыты: клиент и сессия, вход и регистрация, шторка траты (создание, сплиты, «поровну», остаток, редактирование, удаление), список операций и фильтры, категории, бюджеты, аналитика, обзор, профиль, каркас навигации, а также чистая логика (деньги, даты, склонения, сплиты, графики).

## Известные ограничения

- Токен в `localStorage` доступен любому скрипту на странице; защищайтесь строгой CSP. Надёжнее была бы пара «короткий access-токен в памяти + refresh в httpOnly-cookie», но бэкенд этого пока не поддерживает.
- В списке операций нет бесконечной прокрутки, подгрузка по кнопке «Показать ещё».
- Бэкенд отдаёт суммы до четырёх знаков после запятой, клиент показывает и редактирует два. Если в базе лежит трата с «длинными» копейками, при редактировании она будет округлена.
- Основной бандл около 585 КБ (около 166 КБ в gzip): большую часть занимает Chakra UI.
