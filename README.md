# Cash Tracker

![CI](https://github.com/finezhulidov-create/cash-tracker/actions/workflows/ci.yml/badge.svg)

Личный трекер финансов: backend на Spring Boot и веб-клиент на React (папка [`frontend/`](frontend/README.md)). Пользователь ведёт **категории**, добавляет **траты** (одну трату можно разбить на несколько категорий: чек из супермаркета → «Еда» + «Быт»), задаёт **месячные бюджеты** и видит **остаток** и **аналитику** для дашборда.

## Возможности

- Регистрация и вход по email и паролю, JWT. Регистрация сразу возвращает токен.
- Категории пользователя, список кэшируется в Redis.
- Траты с разбивкой на части по категориям; сумма частей обязана равняться сумме траты. Дату можно указать вручную (внести трату задним числом).
- Бюджеты на месяц: **по категории** или **общий** (без категории, считает все траты месяца). Остаток всегда считается из трат при запросе, а не хранится.
- Поиск по описанию траты (параметр `q`, без учёта регистра) и фильтры по категории, сумме и датам.
- Аналитика: траты по категориям за период, динамика по месяцам года, сводка месяца (все траты, общий бюджет и бюджеты категорий с остатками).
- ИИ-советник (необязательно, [подробнее](#ии-советник-gigachat)): разбор трат и бюджетов за месяц на GigaChat от Сбера. По умолчанию выключен.
- Импорт банковской выписки из PDF (необязательно, [подробнее](#импорт-выписки-из-pdf)): локальная модель в LM Studio находит операции, приложение помечает уже внесённые, пользователь отмечает нужные и сохраняет их одной пачкой.
- Баланс пользователя: поле, которое пользователь задаёт сам; от трат не меняется.
- Данные каждого пользователя изолированы: чужой ресурс отвечает 404, как будто его нет.

## Архитектура

```
cash-tracker/
├── cash-tracker-common/         # JWT, обработка ошибок, исключения, утилиты
├── cash-tracker-transactions/   # домен: категории, траты со сплитами, бюджеты, аналитика, импорт PDF-выписок
├── cash-tracker-app/            # запускаемое приложение: пользователи, авторизация, безопасность,
│                                # конфигурация Redis/CORS/Swagger, миграции Liquibase
├── frontend/                    # веб-клиент (React + TypeScript + Vite), отдельный npm-проект
└── deploy/                      # боевой запуск на сервере: Docker Compose, Caddy (HTTPS), инструкция
```

`app` зависит от `transactions` и `common`, `transactions` от `common`; обратных зависимостей нет. Домен трат знает пользователя только по `userId`.

**Запрос.** `RateLimitFilter` (только `/auth/**`) → `JwtFilter` → контроллер → сервис → репозиторий. Идентификатор пользователя берётся только из токена, а не из тела запроса. Владение ресурсом проверяется в сервисе (`SecurityUtils.assertOwner`) на каждом обращении, включая вложенные ссылки (например, категория внутри части траты).

**Кэш.** Список категорий и части трат по категории лежат в Redis (ключи `categories::{userId}` и `splits::{userId}:{categoryId}`, TTL 15 минут), значения хранятся строго типизированно. Кэш сбрасывается при изменении категорий и трат.

**Модель данных** (все связи с пользователем каскадно удаляются вместе с ним):

```
users ──< categories ──< transaction_split >── transaction >── users
users ──< budget            (category_id необязателен: пусто = общий бюджет месяца)
```

Схему ведёт только Liquibase (`ddl-auto=validate`). Применённые changeset'ы не редактируются, изменения идут новыми файлами в `cash-tracker-app/src/main/resources/db/changelog`.

## Быстрый старт

Нужны Docker и Docker Compose.

```bash
docker compose up --build
```

| Что | Адрес |
|---|---|
| API | http://localhost:8080 |
| Swagger UI | http://localhost:8080/swagger-ui/index.html |
| Состояние | http://localhost:8080/actuator/health |

Локальная разработка (нужны запущенные PostgreSQL и Redis, например `docker compose up db redis`):

```bash
mvn spring-boot:run -pl cash-tracker-app -am -Dspring-boot.run.profiles=dev
```

Чтобы проверить в браузере обе ИИ-функции, перед этой командой в том же терминале задайте переменные окружения (ключи не записывайте в файлы репозитория):

```bash
# ИИ-советник: ключ и сертификаты Минцифры (как скачать — в разделе «ИИ-советник»)
export GIGACHAT_ENABLED=true
export GIGACHAT_AUTH_KEY='ключ-из-кабинета-сбера'
export GIGACHAT_CA_CERT_PATH="$HOME/gigachat-certs/root.crt,$HOME/gigachat-certs/sub.crt"

# Импорт выписок: адрес LM Studio, если она не на этом компьютере (по умолчанию http://localhost:1234)
# export LMS_API_URL=http://192.168.31.14:1234
# export LMS_API_KEY=...   # только если в LM Studio включена авторизация
```

В LM Studio должна быть загружена модель с именем из `spring.ai.openai.chat.options.model` (`qwen3.5-9b`) и запущен сервер (Developer → Start Server). Проверка: `curl http://localhost:1234/v1/models`. Контейнер `app` из корневого `docker-compose.yml` для этого не подходит: в нём нет переменных GigaChat, а `localhost` внутри контейнера — сам контейнер, а не ваш компьютер.

Веб-клиент (нужен Node.js 22.12+; бэкенд уже запущен):

```bash
cd frontend
npm install
npm run dev        # http://localhost:5173
```

Подробности, настройка адреса API и сборка для продакшена: [frontend/README.md](frontend/README.md).

## Как работать с API

Все запросы, кроме `/auth/**`, Swagger и Actuator, требуют заголовок `Authorization: Bearer <токен>`. Токен приходит в ответах `POST /auth/register` и `POST /auth/login`:

```json
{ "accessToken": "eyJ...", "tokenType": "Bearer", "expiresIn": 86400 }
```

`expiresIn` — секунды. Токен действует 24 часа, обновления токена нет: по истечении срока пользователь входит заново.

### Эндпоинты

| Область | Эндпоинт | Назначение |
|---|---|---|
| Auth | `POST /auth/register` | Регистрация, сразу возвращает токен |
| | `POST /auth/login` | Вход |
| Профиль | `GET /v1/users/me` | Имя, email, баланс |
| | `PUT /v1/users/me/balance` | Задать баланс, тело `{"balance": 1500.50}` |
| | `DELETE /v1/users/delete` | Удалить аккаунт со всеми данными |
| Категории | `POST/GET/PUT/DELETE /v1/categories[/{id}]`, `GET /v1/categories/mine` | CRUD, список. Удаление категории с тратами: 409 |
| | `GET /v1/categories/{id}/splits` | Части трат в категории |
| Траты | `POST /v1/transactions` | Создать трату с разбивкой |
| | `GET /v1/transactions` | Список: поиск `q` по описанию, фильтры `categoryId`, `minAmount`, `maxAmount`, `from`, `to`, пагинация, сортировка |
| | `GET/PUT/DELETE /v1/transactions/{id}` | Одна трата |
| | `GET /v1/transactions/total?from&to` | Сумма за период |
| Бюджеты | `POST /v1/budgets` | Создать (с `categoryId` или общий) |
| | `GET /v1/budgets?yearMonth=2026-10` | Бюджеты месяца |
| | `GET/PUT/DELETE /v1/budgets/{id}` | Один бюджет |
| | `GET /v1/budgets/{id}/status` | `assigned`, `spent`, `available` |
| Аналитика | `GET /v1/analytics/by-category?from&to` | Траты по категориям (даты `yyyy-MM-dd`, включительно) |
| | `GET /v1/analytics/monthly?year` | 12 месяцев с суммами |
| | `GET /v1/analytics/summary?yearMonth` | Сводка месяца |
| ИИ-советник | `GET /v1/ai/status` | `{"enabled": true}`: включён ли советник на сервере (по нему клиент показывает или прячет экран) |
| | `POST /v1/ai/advice` | Тело `{"yearMonth": "2026-10"}`, ответ `{"text", "generatedAt", "cached"}`: разбор месяца в markdown |
| Импорт выписки | `POST /v1/parsing` | multipart, поле `file` (PDF до 10 МБ). Ответ: найденные траты с пометкой `duplicate`, в базу ничего не пишется |
| | `POST /v1/parsing/save` | Тело `{"transactions": [...]}` (как у `POST /v1/transactions`, до 1000 штук), сохраняет все или ни одной |

Полное описание со схемами и кодами ответов: Swagger UI.

### Создание траты

```json
{
  "description": "Супермаркет",
  "amount": 1000.00,
  "dateTime": "2026-10-28T14:30:00",
  "splits": [
    { "categoryId": 10, "amount": 700.00 },
    { "categoryId": 11, "amount": 300.00 }
  ]
}
```

`dateTime` необязателен: без него берётся текущее время сервера (UTC). Время хранится и возвращается **без часового пояса, как его ввёл пользователь**, месяц бюджета определяется по этой дате. Сумма частей должна равняться `amount`, иначе 400 `NOT_VALID_TRANSACTION_SPLIT_SUM`.

### Списки и пагинация

Списки возвращаются в формате `{ "content": [...], "page": { "size", "number", "totalElements", "totalPages" } }`. Параметры: `page` (с нуля), `size`, `sort=поле,asc|desc`. Список трат по умолчанию идёт от новых к старым.

### Формат ошибок

Все ошибки приходят в одном виде, `errors` есть только у ошибок валидации (поле → сообщение):

```json
{
  "status": 400,
  "message": "Validation failed",
  "timestamp": "2026-10-28T14:30:00",
  "errorCode": "VALIDATION_ERROR",
  "errors": { "splits[0].amount": "must be greater than 0" }
}
```

| Статус | `errorCode` | Когда |
|---|---|---|
| 400 | `VALIDATION_ERROR`, `MALFORMED_REQUEST`, `MISSING_PARAMETER`, `INVALID_PARAMETER`, `INVALID_REQUEST`, `INVALID_SORT`, `NOT_VALID_TRANSACTION_SPLIT_SUM` | Некорректный запрос |
| 401 | `UNAUTHORIZED`, `INVALID_CREDENTIALS` | Нет или невалиден токен; неверный email или пароль |
| 403 | `FORBIDDEN` | Нет прав |
| 404 | `RESOURCE_NOT_FOUND`, `ACCESS_DENIED`, `NOT_FOUND` | Не найдено, **либо ресурс чужой** |
| 409 | `EMAIL_ALREADY_EXISTS`, `RESOURCE_ALREADY_EXISTS`, `CATEGORY_IN_USE`, `DATA_INTEGRITY_VIOLATION` | Конфликт |
| 429 | `RATE_LIMIT_EXCEEDED` | Превышен лимит запросов к `/auth/**` |
| 429 | `AI_BUSY`, `AI_RATE_LIMIT_EXCEEDED` | ИИ-советник: модель занята другим запросом; исчерпан личный лимит анализов. Есть `Retry-After` |
| 502 | `AI_BAD_RESPONSE` | ИИ-советник: модель вернула пустой или непригодный ответ |
| 503 | `AI_DISABLED`, `AI_UNAVAILABLE`, `AI_AUTH_FAILED`, `AI_QUOTA_EXHAUSTED` | ИИ-советник: не настроен; сервис Сбера недоступен; ключ не принят; закончились токены |
| 502 | `IMPORT_BAD_RESPONSE` | Импорт выписки: модель не вернула пригодный JSON ни для одной страницы |
| 503 | `IMPORT_MODEL_UNAVAILABLE` | Импорт выписки: LM Studio недоступна или модель не загружена |
| 500 | `INTERNAL_ERROR` | Сбой сервера (без внутренних деталей, они только в логе) |

### Для фронтенда

- **Вход.** Токен передаётся заголовком, cookie и CSRF не используются. При 401 направляйте пользователя на экран входа. Клиент из `frontend/` хранит токен в `localStorage`: это просто, но любой XSS его прочитает, поэтому в продакшене нужна строгая CSP и никаких сторонних скриптов; безопаснее было бы перейти на httpOnly-cookie с refresh-токеном (бэкенд пока этого не умеет).
- **CORS.** Разрешённые адреса задаются в `app.cors.allowed-origins` (по умолчанию `http://localhost:3000` и `http://localhost:5173`).
- **Лимит.** При 429 ответ содержит заголовок `Retry-After` (секунды); он доступен браузеру (`Access-Control-Expose-Headers`).
- **Деньги** приходят десятичными числами, из базы до 4 знаков после запятой (`1000.0000`). Не используйте float для расчётов, форматируйте сумму при отображении.
- **Генерация клиента.** Спецификация: `GET /v3/api-docs` (можно подать в openapi-generator).

| Свойство | По умолчанию | Назначение |
|---|---|---|

| `spring.data.redis.host/port` | профиль `dev`: localhost:6379 | Redis |
| `jwt.secret` (`JWT_SECRET`) | в `dev` есть значение по умолчанию | Секрет подписи: **base64-строка от 32 байт**, например `openssl rand -base64 48` |
| `jwt.expiration` | `86400000` | Срок жизни токена, мс |

| `app.rate-limit.auth.enabled` | `true` | Выключатель лимита |
| `gigachat.enabled` (`GIGACHAT_ENABLED`) | `false` | Включает ИИ-советника. Если `true`, а ключа нет, приложение не запустится |
| `gigachat.auth-key` (`GIGACHAT_AUTH_KEY`) | пусто | Ключ авторизации GigaChat API из личного кабинета Сбера. Только в окружении, не в файлах репозитория |
| `gigachat.ca-cert-path` (`GIGACHAT_CA_CERT_PATH`) | пусто | Файлы корневых сертификатов Минцифры через запятую (PEM или DER) |
| `spring.ai.openai.base-url` (`LMS_API_URL`) | `http://localhost:1234` | Адрес OpenAI-совместимого сервера с моделью для разбора выписок, без `/v1` |
| `spring.ai.openai.api-key` (`LMS_API_KEY`) | `lm-studio` (`prod`: `none`) | Ключ сервера модели. LM Studio без авторизации принимает любое значение, но пустым его оставлять нельзя |
| `spring.ai.openai.chat.options.model` | `qwen3.5-9b` | Имя модели, как оно показано в LM Studio |
| `spring.ai.openai.chat.options.reasoning-effort` | `none` | Выключает «размышления» думающих моделей: с ними страница разбирается минутами, без них — секунды |
| `spring.http.client.connect-timeout` / `read-timeout` | `5s` / `5m` | Таймауты запросов к модели: недоступная LM Studio даёт ошибку через 5 секунд, а не зависание |
| `spring.servlet.multipart.max-file-size` / `max-request-size` | `10MB` | Предельный размер загружаемой выписки. Веб-клиент проверяет тот же предел до отправки (`MAX_STATEMENT_SIZE`) |

Остальные настройки советника (`gigachat.*`) имеют значения по умолчанию: модель `GigaChat-2-Pro`, 10 новых анализов в час на пользователя, кэш ответа 6 часов, ожидание очереди 30 секунд, чтение ответа 90 секунд. Полный список: `AiProperties`.

Рейт-лимит считается по `getRemoteAddr()`. За обратным прокси там будет адрес прокси, и лимит станет общим на всех клиентов: передавайте реальный IP (`server.forward-headers-strategy=native` и настройки Tomcat remote IP). Если Redis недоступен, лимит не применяется, а вход продолжает работать.

## ИИ-советник (GigaChat)

Анализ месяца: приложение собирает сводку (траты, бюджеты, прошлый месяц), отправляет её GigaChat и показывает ответ. Все проценты и статусы («в норме», «85% и больше», «перерасход») считает код, а не модель; модель только комментирует и советует. Код лежит в модуле `app`, пакет `ai`; основной домен (`transactions`) от Сбера ничего не знает.

**Что уходит в Сбер.** Месяц, итоги, названия категорий (до 50 символов, без управляющих символов), траты и бюджеты по ним, траты прошлого месяца. Не уходят: email, имя, пароль, идентификаторы, описания отдельных трат. Тем не менее это ваши финансовые данные на стороннем сервисе: включайте советник осознанно. Названия категорий вводит пользователь, поэтому текст запроса к модели сформирован так, чтобы данные внутри JSON не считались инструкциями.

**Как это защищено**

- Выключен по умолчанию; включённый без ключа не стартует, ошибка в конфигурации видна сразу, а не при первом запросе.
- Ключ только из окружения, в ответы и логи не попадает; ответы ошибок не содержат деталей Сбера.
- Проверка TLS не отключается. Сертификаты Минцифры (нужны серверам Сбера, Java им по умолчанию не доверяет) добавляются к стандартным доверенным через `gigachat.ca-cert-path`.
- Токен доступа GigaChat живёт 30 минут и обновляется сам; при ответе 401 запрос повторяется один раз с новым токеном.
- Расходы ограничены: личный лимит (счётчик в Redis; при недоступном Redis платные запросы отклоняются, а не пропускаются), кэш ответа по отпечатку данных (повтор без изменений ничего не стоит и лимит не тратит), неудачный запрос лимит возвращает.
- Запросы к GigaChat идут по одному: у физлица один поток. Остальные ждут до 30 секунд, потом получают 429 `AI_BUSY`.
- Ответ модели в вебе показывается как markdown без HTML, без картинок и ссылок.

**Ограничения.** Ответ формируется до минуты и дольше. Это совет нейросети, а не финансовая рекомендация. «Сегодня» сервер считает по UTC. Месяц, который уже наступил в часовом поясе UTC+14, принимается; будущий — нет. Живое соединение со Сбером в тестах не проверяется: тесты используют подмену на локальном порту. Развёртывание и подключение сертификатов: [`deploy/README.md`](deploy/README.md#11-ии-советник-необязательно).

## Импорт выписки из PDF

Пользователь загружает PDF-выписку из банка, видит найденные траты, отмечает нужные и сохраняет их одной пачкой. Код лежит в модуле `transactions`, пакет `importpdf`.

**Как это работает**

1. `POST /v1/parsing` (multipart, поле `file`): PDFBox достаёт текст постранично, модель в LM Studio по промпту `cash-tracker-app/src/main/resources/ai/parser-prompt.md` превращает каждую страницу в JSON со строками операций (дата, описание, сумма — как в тексте, без вычислений). Суммы и даты разбирает код (`StatementValues`): поддерживаются `-1 234,56 ₽`, `+15 000,00`, `28.10.2026 14:30`, ISO и дата без времени. Строки, которые не удалось разобрать, пропускаются.
2. Поступления (сумма со знаком `+`) отбрасываются: в приложении учитываются только траты.
3. Все операции получают категорию «Прочее» пользователя; если её нет, она создаётся. В предпросмотре категорию можно сменить.
4. Ответ — предпросмотр (`ImportPreviewItem`): операции с пометкой `duplicate`. В базу на этом шаге ничего не пишется.
5. `POST /v1/parsing/save` с `{"transactions": [...]}` (до 1000 штук): каждая операция проверяется как обычная трата и сохраняется в **одной транзакции** — либо все, либо ни одной.

**Дубли.** Ключ операции — минута и сумма (описание не участвует: его каждый раз заново пишет модель, и текст может немного отличаться). Для дат выписки одним запросом берутся траты пользователя, и для каждой операции считается, сколько таких уже есть: две одинаковые покупки в одну минуту не склеиваются в одну, а повторная загрузка той же выписки помечает всё. Дубли в предпросмотре не отмечены, но пользователь может добавить их сам. Ограничение: если импортированную трату потом отредактировать (время или сумму), при следующей загрузке она не узнается.

**Данные.** Текст выписки уходит только на сервер LM Studio, адрес которого вы указали; во внешние сервисы он не отправляется. Описания операций модель видит целиком, поэтому LM Studio стоит держать в своей сети.

**Ошибки.** Файл не PDF — 400 `INVALID_REQUEST`, больше 10 МБ — 413. LM Studio недоступна (неверный адрес, сервер выключен, модель не загружена) — 503 `IMPORT_MODEL_UNAVAILABLE` через 5 секунд, на первой же странице. Модель ответила не JSON — страница пропускается; если так со всеми страницами — 502 `IMPORT_BAD_RESPONSE`. Подробности только в логе бэкенда: там видно, какая страница отправлена модели, сколько операций найдено и за сколько миллисекунд.

**Модель.** Подойдёт любая, которая умеет отвечать JSON. Думающие модели (например, `qwen3.5`) приложение просит не рассуждать (`reasoning_effort=none`): с рассуждениями страница из десятка операций разбиралась больше 5 минут и упиралась в таймаут, без них — около 20 секунд на ноутбуке. Маленькие модели иногда искажают описания операций, поэтому перед сохранением всегда есть предпросмотр.

**Ограничения.** Разбор идёт по странице и занимает от десятков секунд до нескольких минут. Операция на стыке страниц может разорваться или потеряться: проверяйте предпросмотр. Лимита запросов на разбор пока нет. Без LM Studio приложение запускается и работает, падает только сам разбор. Развёртывание: [`deploy/README.md`](deploy/README.md#12-импорт-выписок-необязательно).

## Эксплуатация

- `GET /actuator/health` — общее состояние (БД и Redis), `/actuator/health/liveness` и `/readiness` — для оркестраторов. Детали компонентов наружу не отдаются. Открыты только `health` и `info`.
- Healthcheck приложения настроен в `docker-compose.yml`.
- Swagger UI и `/v3/api-docs` открыты без токена. При публичном развёртывании их стоит закрыть или выключить.

## Тесты

```bash
mvn verify                              # всё: юнит- и интеграционные тесты, отчёты покрытия
mvn test -DexcludedGroups=integration   # только быстрые тесты, Docker не нужен
```

- **Юнит-тесты** (Mockito, `@WebMvcTest`): сервисы, контроллеры, валидация, формат ошибок, фильтры безопасности, конфигурация безопасности и CORS.
- **Интеграционные тесты** (`@Tag("integration")`, Testcontainers): настоящие PostgreSQL и Redis, полная цепочка безопасности, миграции Liquibase, сквозные сценарии API, кэш, рейт-лимит, Actuator, OpenAPI. Требуют запущенного Docker.
- **Покрытие (JaCoCo).** После `mvn verify`: `cash-tracker-app/target/site/jacoco-aggregate/index.html` (модули `common` и `transactions`) и `cash-tracker-app/target/site/jacoco/index.html` (классы `app`). Сгенерированные MapStruct-мапперы в отчёт не входят.

Тесты веб-клиента: `cd frontend && npm test` (Vitest + Testing Library + MSW, сеть мокается на уровне HTTP, бэкенд не нужен).

## CI

GitHub Actions (`.github/workflows/ci.yml`) на каждый push и pull request: `mvn verify` со всеми интеграционными тестами, публикация отчёта покрытия, отдельная проверка сборки Docker-образа и отдельный job веб-клиента (проверка типов, линтер, тесты, сборка).

## Известные ограничения

- Токен живёт 24 часа, обновления токена и выхода из системы на сервере нет.
- Подтверждения email и сброса пароля нет.
- Баланс пользователя задаётся вручную и не связан с тратами.
- Время хранится без часового пояса (так, как его ввёл пользователь).
- Секрет JWT проверяется только при выдаче первого токена: при неверном формате приложение стартует, а вход и регистрация отвечают 500 (в `deploy/README.md` это описано, проверка при старте не реализована).
